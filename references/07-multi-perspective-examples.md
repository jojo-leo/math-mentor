# 07 · 多视角案例库

在 `learn` 模式中，默认**直接给案例/类比**，不模拟完整的小组讨论。

这个文件收集常见的抽象概念 → 多视角具体案例的对应关系。

---

## 使用原则

**何时使用**：用户理解了公式，但缺少"为什么现实中会这样"的直觉。

**如何使用**：
1. 从 2-3 个不同视角给案例（工程/社会学/经济学/物理类比）
2. 每个案例 2-3 句话，点到为止
3. 不模拟对话，直接陈述

**例子**（对比）：

❌ **不要这样**（模拟对话）：
> **[Bob]**: 我之前在播客平台实习...  
> **[Elena]**: Bob 你这个例子很好，我想补充...  
> **[你]**: （等待用户插话）

✅ **应该这样**（直接陈述）：
> 从三个角度理解"平台为什么可能收集不足"：
> 
> **工程实践**：小众播客平台不做推荐算法，因为投入 10 万成本，但订阅费固定（9.9 元/月），用户对推荐质量不敏感，收入增加不到 1 万。平台算不过账。
> 
> **社会学视角**：类似"企业不愿培训员工"（培训后员工可能跳槽）。正外部性（整个行业受益）无法内部化，导致投资不足。
> 
> **经济学类比**：餐厅做精致菜单（策略 B）vs. 简单菜单（策略 A）。顾客省时间的价值很高，但老板提取不了这个价值，选择策略 A。

## 案例库（按主题）

### 主题 1：外部性（Externalities）

**抽象概念**：私人成本/收益 ≠ 社会成本/收益

**正外部性（投资不足）**：
- **教育**：个人读书受益，整个社会也受益（高素质公民），但个人只看自己收益 → 教育投资不足，需要政府补贴
- **疫苗接种**：我打疫苗保护自己，也保护别人（群体免疫），但我只看自己的成本收益 → 接种率不足
- **数据收集（论文）**：平台做推荐算法，用户节省时间（社会收益），但平台提取不了全部价值 → 投资不足

**负外部性（过度使用）**：
- **污染**：工厂排污降低自己成本，但社会承担环境损失 → 过度排污
- **数据收集（论文）**：平台收集数据提高推荐，但不承担用户的隐私成本 → 过度收集

### 主题 2：信息不对称（Information Asymmetry）

**抽象概念**：一方知道信息，另一方不知道

**柠檬市场**（Akerlof）：
- **二手车市场**：卖家知道车况，买家不知道 → 买家只愿意出"平均车况"的价，好车退出市场，剩下烂车
- **数据平台**：平台知道推荐质量提升的价值，用户不知道 → 用户不愿意为"更好的推荐"付钱

**信号传递**（Signaling）：
- **学历**：能力高的人读大学（成本低），能力低的人读不起（成本高） → 学历成为能力信号
- **隐私政策**：平台展示"我们保护隐私"的认证，试图传递"我们不会过度收集"的信号

### 主题 3：委托-代理问题（Principal-Agent）

**抽象概念**：委托人（principal）目标 ≠ 代理人（agent）目标

**经典案例**：
- **医生-患者**：患者想治好病（健康），医生想赚钱（收入） → 过度医疗
- **平台-用户**：用户想好推荐 + 低隐私成本，平台想利润最大化 → 可能过度或不足收集数据
- **基金经理-投资者**：投资者想长期回报，经理想短期业绩（年终奖） → 过度冒险

### 主题 4：市场结构与竞争

**垄断 vs. 竞争**：

**垄断的双面性**：
- **坏处**：定价高、产量少（经典教科书）
- **好处**：可以做长期投资（如 R&D），因为不怕竞争对手抢走收益
- **数据收集**：垄断平台可能收集少（懒得投资）或多（没人制约）

**竞争的双面性**：
- **好处**：降价、提高质量（经典教科书）
- **坏处**：军备竞赛（如广告战、数据收集竞赛），总成本高但对消费者福利提升有限
- **数据收集**：竞争平台可能过度收集（囚徒困境）

**现实例子**：
- **外卖平台补贴战**：美团 vs 饿了么，疯狂烧钱，短期对消费者好（便宜），长期不可持续
- **社交媒体隐私竞赛**：如果一家平台收集很多数据，对手也被迫收集（否则推荐质量落后） → 集体过度收集

### 主题 5：时间不一致性（Time Inconsistency）

**抽象概念**：现在的我 vs. 将来的我，偏好不同

**经典案例**：
- **健身承诺**：今天的我说"明天开始健身"，明天的我说"后天吧" → 永远不开始
- **储蓄不足**：今天的我想花钱，将来的我需要养老金 → 储蓄不足，需要强制储蓄（如社保）
- **数据隐私**：今天的我"无所谓，反正方便"，将来的我"完蛋了，信息都泄露了" → 过度分享数据

### 主题 6：网络效应（Network Effects）

**抽象概念**：用户越多，平台价值越高

**正网络效应**：
- **社交媒体**：朋友都在 Facebook/微信，你也得用 → 赢家通吃
- **数据平台**：用户越多 → 数据越多 → 推荐越准 → 吸引更多用户 → 正反馈

**负网络效应（拥挤）**：
- **餐厅**：人太多，服务质量下降
- **平台**：用户太多，内容质量下降（如小红书早期 vs 现在）

### 主题 7：边际效用递减 vs 边际成本递增

**抽象概念**：多一个的好处递减，成本递增

**边际效用递减**：
- **包子**：第一个很爽，第二个还行，第三个撑了
- **推荐质量**：从 50% → 70% 提升很大，从 90% → 95% 提升很小

**边际成本递增**：
- **加班**：前 2 小时效率高，后面越来越累（每小时产出递减）
- **隐私成本**：收集基本信息（性别年龄）用户无所谓，收集敏感信息（位置聊天记录）用户很反感

**权衡点**：$\text{边际效用} = \text{边际成本}$（最优点）

## 使用建议

1. **不要一次给太多案例**（2-3 个够了）
2. **选和用户背景相关的**（社科用户 → 多给社会学/经济学案例；工科用户 → 多给工程例子）
3. **案例后立即连回公式**（如"这就是为什么 $d^M < d^{SO}$ 的情况"）
4. **让用户自己举例**（如"你能想到其他类似的例子吗？"）
