# 概念卡 Schema

每个概念卡是一个 Markdown 文件，文件名 = 概念的 slug（如 `cox-proportional-hazards.md`）。

新概念第一次出现时，按这个模板现写一张卡，以后复用。

---

## 写卡时的原则

1. **简洁优先**。概念卡不是教材，是速查 + 学习路线图。每个 section 控制在 100-300 词。
2. **可验证**。数值例子必须算过，不能编。资源链接要检查（写书名+章节比写 URL 更稳定）。
3. **面向用户**。根据档案调整深度。如果用户是社科背景，"直觉"部分多写实证例子；如果是工科背景，多写算法。
4. **模块化**。每个 section 独立，用户可以只看某一部分（如只看"实现"跳过"数学定义"）。
5. **留白**。如果某个 section 暂时空缺（如"还没写 PBL 项目种子"），写 `[待补充]`，以后再填。
